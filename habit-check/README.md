# 習慣チェック（PWA）

Notion の「🌅 習慣」ページの5つのタブ（習慣チェック・パーティー・ギルド・ものがたり・きろく）と、
たまごから育つ相棒「あいぼう」を、スマホの1画面ずつで見て・入力できるWebアプリ。木目調。ホーム画面に追加するとアプリのように使える。

| 下のメニュー | 中身 | 読む／書くDB |
| --- | --- | --- |
| 習慣 | 日（時間帯ごとにチェック・ひとこと）／週（7日分の表でチェック）／カレンダー（1か月の達成度）／グラフ（直近14日の達成率・よくできている／伸びしろ） | DB_習慣チェック（読む・書く） |
| あいぼう | たまごから育つペット1体。ドット絵・段階・傾向4本・次の進化まで・ひとこと。習慣をチェックすると日画面にも小さく出てくる | DB_あいぼう（読む・書く）、DB_習慣チェック と DB_タスク管理（読む） |
| パーティー | ひょうじ が付いた「すがた」を絵つきで並べる。いまのすがたに「いま」 | DB_すがた（読む） |
| ギルド | けいじばん（依頼の一覧・カテゴリで絞る・段階と寄り道）／ほうこく（達成の記録）。依頼を開いて「ほうこくする」で達成記録に1行足す | DB_ギルド依頼（読む）、DB_ギルド達成記録（読む・足す） |
| ものがたり | ほんぺん／よりみちの章の一覧。Lvが足りない章はロック。開くと本文を読めて「よんだ」を付けられる | DB_ものがたり（読む・よんだ だけ書く） |
| きろく | Lv・総EXP・次のLvまで、EXPのうちわけ、ステータス・なかま・じゅもん | DB_プレイヤー（読む） |

- 習慣の一覧は DB_習慣チェック の**チェックボックス列から毎回読み込む**。列を増やす・名前を変えるだけでアプリにも反映される
- 列名の記号で並びが決まる：◆必ず ◇できれば ／ ☼朝 ☀︎昼 ◷時間指定 ☾夜 ↻いつでも（今の時間帯が一番上）
- 列の「説明」（例：最小版：1ページ）が習慣名の下に出る
- ひとこと（+5EXP）も入力できる
- 6日前までさかのぼってチェックできる（夜中に前日分をつけるとき用）。それより前はカレンダーから見るだけ
- Lv・EXP・ステータスは、EXP（習慣・タスク・ギルド）の合計だけ Notion から全件で取り直し、レベル・次のLvまで・ステータスは DB_プレイヤーと同じ式で計算し直す（Notion API はページの rollup を関連の先頭25件だけで計算するため。DB_プレイヤーの式を変えたら `src/worker.js` の `levelOf`・`statusText` も合わせる）。パーティーの表示・ものがたりのロック・ギルドの受注Lvもこのレベルで判定する
- 基本はスクロールなしの1画面。習慣が多い時間帯や依頼の一覧など、長いときだけその枠の中がスクロールする

## あいぼう

- 「たまごを うけとる」で DB_あいぼう に1行できる（1体だけ）。その日が誕生日
- **育ち方**：誕生日からの EXP（習慣チェックの EXP＋DB_タスク管理 の DONE タスクの討伐EXP）で、たまご → 幼体 → 成長期（4種）→ 成体（5種）
  - 習慣1つのEXPは DB_習慣チェック「EXP」の式と同じ重み（◆5／◇★10、ひとこと+5）で、行の EXP をそれぞれの型へ振り分ける
  - 成長期の型＝幼体の間に一番多く貯めた傾向。成体の型＝成長期の間に一番多く貯めた傾向。4つの差（最大−最小）が期間合計の10%以内なら、隠しの「バランス型」
  - しきい値を越えた日に進化（その日のぶんは前の段階に数える）。進化した段階・型・日付は DB_あいぼう に書き、後でチェックを外しても戻らない
  - EXP と傾向ポイントは保存せず、開くたびに計算する（チェックを外すとその分は減る）
  - 空腹・弱る・死ぬ・ストリークは無し。その日のEXPが0なら寝ている
- **設定は `src/aibou-config.js` だけ**：習慣名のキーワード → 型、分類タグ → 型、しきい値（いまは 孵化300／成長期4,000／成体18,000。2026-10-28 時点の1日平均 約300EXP から、孵化≒1日・成長期≒2週間・成体≒2か月）。どれにも当たらない習慣・タグは4つの型に均等割り
- **絵**：`public/aibou-sprites.js`（32×32 のピクセル配列）を `scripts/make-aibou-sprites.mjs` で作る。絵を直したら `node scripts/make-aibou-sprites.mjs`
- **3D に差し替えるとき**：`public/assets/aibou/` に `01_egg.glb`〜`11_adult_balance.glb`（名前は `public/aibou.js` の `MODEL_FILES`）と、`mount(要素, GLBのURL, 動き)` を持つ `public/aibou-3d.js` を置くと、そのキャラだけ自動で 3D 表示になる（無いキャラはドット絵のまま）
- 進化の演出は、その端末で最後に見た段階と違うときに出る（端末ごと）
- アーティファクト版（MCP）では使えない（計算式の値が読めないため）

## 2つの動かし方

| | アーティファクト版（MCP） | Cloudflare版 |
| --- | --- | --- |
| 開き方 | claude.ai のアーティファクト（[習慣チェック](https://claude.ai/artifact/2Qh2SswrkppSsvWsiat4bV)）を開く | 自分の `workers.dev` のURLを開く |
| Notion への入り方 | 見ている人の claude.ai の Notion 連携（MCP）。トークン・合言葉・サーバーなし | Notion のインテグレーションのトークン（Cloudflare の秘密の値） |
| 準備 | なし（初回に「Notion を使ってよいか」の確認が出たら許可） | 下の「セットアップ」 |
| Lv・EXP・ステータス・なかま・じゅもん | 出ない（「—」）。Notion の MCP は数式・ロールアップの値を返さないため | 出る |
| ギルドの達成回数 | 達成記録の数で出す。累計EXP・けいじばん・寄り道は出ない | 出る |
| パーティー | 表示条件（数式）が読めないので、すがたを全部出す | ひょうじ が付いたものだけ |
| ものがたりのロック | Lv が分からないのでロックしない | Lv が足りない章はロック |
| 習慣の列 | 「🌅 習慣」ページのビュー「✅ 習慣チェック」で**表示している列だけ**を、ビューの並びで出す（非表示にした列は出さず、書き込みもしない） | `wrangler.toml` の `HIDDEN_HABITS` に書いた列を出さない（Notion API ではビューの表示設定が読めないため、Notion で非表示にしたらここにも書く） |

アーティファクト版の /api は `src/mcp-api.js` が画面の中で答える（Worker と同じ返事の形）。
書き換えるのは Cloudflare版と同じ3つだけで、さらに「この画面で読み込んだ行・依頼・章」に限る。

```sh
node scripts/build-artifact.mjs   # dist/artifact.html を作る（公開は Claude に「アーティファクトを更新して」）
```

公開するときは capabilities に `{"mcp": {"servers": [{"server": "Notion", "tools": ["notion-fetch", "notion-query-data-sources", "notion-update-page", "notion-create-pages"]}]}}` を宣言する。

## しくみ（Cloudflare版）

```
iPhone（ホーム画面のアプリ） ──合言葉──▶ Cloudflare Worker ──トークン──▶ Notion API
                                          （画面の配信＋中継）
```

- Notion のトークンは **Cloudflare 側の秘密の値にだけ**置く。スマホやブラウザ、社内PCには残らない
- Worker が書き換えるのは次の4つだけ（それ以外のページ・列は拒否）
  - DB_習慣チェック の行の「チェック列」と「ひとこと」
  - DB_ギルド達成記録 への行の追加（DB_ギルド依頼 の依頼に紐づけたものだけ）
  - DB_ものがたり の「よんだ」（Lvが足りない章は読む・書くとも拒否）
  - DB_あいぼう の行（たまごの1行を作る・名前・進化した段階／型／進化履歴）
- アプリを開くには合言葉（APP_KEY）が必要。合言葉は端末のブラウザにだけ保存される
- Cloudflare Workers の無料枠で動く

## セットアップ（Cloudflare版・PCのブラウザだけでできる）

### 1. Notion：インテグレーションを作る

1. https://www.notion.so/profile/integrations で「新しいインテグレーション」→ 種類：内部、名前：習慣チェック
2. 機能は「コンテンツを読み取る」「コンテンツを更新」「コンテンツを挿入」だけON（コメント・ユーザー情報はOFF）
3. シークレット（`ntn_…`）をコピーしておく（Notionのページには貼らない）
4. Notion で **DB_習慣チェック** を開き、右上「•••」→「接続」→「習慣チェック」を追加
5. 同じく次のDBにも接続する（習慣ページの各タブの元のDB）
   - **DB_プレイヤー**（きろく・Lv表示）
   - **DB_すがた**（パーティー）
   - **DB_ギルド依頼** と **DB_ギルド達成記録**（ギルド）
   - **DB_ものがたり**（ものがたり）
   - **DB_あいぼう**（あいぼう）と **DB_タスク管理**（タスクEXP。あいぼうはタスクのDONEでも育つ）
   - ME・データベースなどの親ページには接続しない
   - データソースIDは `wrangler.toml` の `[vars]` に書いてある（IDだけでは読み書きできない。権限はこの接続で決まる）

### 2. Cloudflare：Worker を作る

1. https://dash.cloudflare.com に無料登録（個人のメールアドレスで）
2. 「Workers & Pages」→「作成」→「Gitリポジトリをインポート」→ GitHub の `my-apps` を選ぶ
3. 設定
   - プロジェクト名：`habit-check`
   - ルートディレクトリ：`habit-check`
   - ビルドコマンド：空欄／デプロイコマンド：`npx wrangler deploy`
4. デプロイ後、Worker の「設定」→「変数とシークレット」で **シークレット**を2つ追加して再デプロイ
   - `NOTION_TOKEN`：手順1でコピーした `ntn_…`
   - `APP_KEY`：合言葉（16文字以上。パスワードマネージャーで作ると楽）
5. `https://habit-check.<あなたのサブドメイン>.workers.dev` が表示されたら完了

以後、このフォルダを GitHub で更新すると自動で再デプロイされる。

### 3. iPhone：ホーム画面に追加

1. Safari で上のURLを開き、合言葉を入れる
2. 共有ボタン →「ホーム画面に追加」

## よくあるエラー

| 表示 | 原因 |
| --- | --- |
| 合言葉が違います | APP_KEY と違う。下の「合言葉を消す」から入れ直す |
| インテグレーションが接続されていません | 手順1-4 の接続忘れ |
| Notion のトークンが正しくありません | NOTION_TOKEN の貼り間違い |
| Worker の設定が足りません | シークレット2つが未設定、または APP_KEY が16文字未満 |
| Lv が「—」のまま | DB_プレイヤー に接続していない（手順1-5） |
| パーティー・ギルド・ものがたりで「接続されていません」 | そのタブのDBに接続していない（手順1-5） |
| 依頼の 達成回数・累計EXP が 0 のまま | DB_ギルド達成記録 に接続していない（数式が記録を数えられない） |
| あいぼうで「接続されていません」 | DB_あいぼう か DB_タスク管理 に接続していない（手順1-5） |
| AIBOU_DS_ID（TASK_DS_ID）が設定されていません | `wrangler.toml` の `[vars]` に無い |
| あいぼうが育たない・タスクのぶんが入らない | DB_タスク管理 に接続していない、またはタスクに「完了日」が無い（DONE の日で数える） |
| あいぼうは Cloudflare版だけで使えます | アーティファクト版で開いている |
| この日の行がまだありません | Notion の自動作成より先に開いた。「行を作る」で作れる（二重には作らない） |

## 開発

```sh
npm install
npm test               # Worker とアーティファクト版 /api のテスト（Notion は偽物に差し替え）
npx wrangler dev       # ローカルで起動（.dev.vars に NOTION_TOKEN と APP_KEY を書く）
node scripts/build-demo.mjs   # 動かせるデモ dist/demo.html を作る（Notion には通信しない）
```

- `src/worker.js`：Notion API の中継（API バージョン 2025-09-03、データソース指定）
- `src/aibou-config.js`：あいぼうの育ち方（習慣・タグ → 型、しきい値）
- `public/aibou.js`：あいぼうの描画（`renderPet`）・セリフ・進化のひとこと。`public/aibou-sprites.js` がドット絵
- `scripts/make-aibou-sprites.mjs`：あいぼうのドット絵（11体）の生成
- `src/mcp-api.js`：アーティファクト版の /api（Notion 連携＝MCP 経由）。テストの偽連携は `test/fake-notion-mcp.mjs`
- `public/`：画面（HTML/CSS/JS、サービスワーカー、アイコン）
- `scripts/make-icons.py`：アイコン画像の生成
- `scripts/make-wood.py`：木目の背景画像（`public/img/walnut.jpg`・`oak.jpg`）の生成
- `scripts/build-demo.mjs`：本物の画面に偽の /api を組み込んだ1ファイルのデモ（Notion のタスクページに埋め込む用）。画面を直したら作り直す
- `scripts/build-artifact.mjs`：アーティファクト版の1ファイル。`scripts/inline-page.mjs`（画面を1ファイルにまとめる部分）をデモと共用
