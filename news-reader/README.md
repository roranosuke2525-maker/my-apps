# けさの新聞（PWA）

Notion の **DB_ニュース**（平日朝の「朝のニュース収集」で集めた日経・時事・東京・上毛の記事）を、
スマホの1つのアプリで読むためのWebアプリ。記事はアプリの中で本文まで読める。
ホーム画面に追加すると、**アイコンに未読の数が赤丸で出る**。

| 画面 | 中身 |
| --- | --- |
| 一覧（未読／最近3日／📚 送った） | 2社以上が扱った話題はまとめて並べ、残りは全国・地元に分ける。上の新聞社のボタンで絞り込める。題字の横の赤丸と各ボタンの数字が未読の数 |
| 記事 | 見出し・一言要約・本文（リーダー表示）・同じ話題の他社の記事。開くと「読んだ」になる。下のボタンで「未読に戻す」「📚 送る」「次の記事」 |
| ホーム画面のアイコン | 未読の数を赤丸で出す。平日 7:15 ごろ、今朝の未読数と主な話題を通知する |

- 「📚 送る」にした記事は、翌朝の定期実行が DB_タスク管理 に 📚 REFERENCE を作る（今までどおり）
- 有料記事（🔒）は無料で読める部分まで。続きは右上の「元の記事を開く」から
- 書き換えるのは DB_ニュース の「状態」（未読・読んだ・📚 送る）だけ

## 本文の読み込み（リーダー表示）

日経・東京・上毛のサイトは、記事を他のサイトに埋め込むこと（iframe）を禁止している。
そこで Worker が記事ページを取りに行き、本文の段落だけを抜き出してアプリに表示する（Safari のリーダー表示と同じ考え方）。

- 取りに行くのは **DB_ニュース にある記事のURL** で、**`ALLOWED_HOSTS` に書いたサイトだけ**（`wrangler.toml`）
- 抜き出した本文は Notion には保存しない。Cloudflare のキャッシュに6時間だけ置く
- サイトごとの本文の場所は `src/extract.js` の `SITES`。サイトの作りが変わって読めなくなったら、ここを直す（読めないときは一言要約と「元の記事を開く」を出す）
- 朝日・読売・毎日を手で追加したときは、決まった場所が無いので「一番長い段落のまとまり」を本文として読む

## しくみ

```
iPhone（ホーム画面のアプリ） ──合言葉──▶ Cloudflare Worker ──トークン──▶ Notion API（DB_ニュース）
        ▲                                 │  └───────────▶ 新聞社のサイト（本文の読み込み）
        └──── 平日 7:15 の通知（中身なし）──┘  ※通知を受けたアプリが未読数を読んでアイコンの数字を更新
```

- Notion のトークンは **Cloudflare 側の秘密の値にだけ**置く。スマホやブラウザ、社内PCには残らない
- アプリを開くには合言葉（APP_KEY）が必要。合言葉は端末のブラウザにだけ保存される
- 通知の鍵（VAPID）と通知の宛先は Cloudflare の KV（`NEWS_KV`）に置く。KV は初回のデプロイで自動で作られ、鍵は Worker が初回に自分で作る（手で入れる秘密の値は増えない）
- Cloudflare Workers の無料枠で動く

## セットアップ（PCのブラウザだけでできる）

### 1. Notion：DB_ニュース にインテグレーションを接続する

1. https://www.notion.so/profile/integrations で「新しいインテグレーション」→ 種類：内部、名前：新聞
   （習慣チェックのインテグレーションを使い回してもよい。そのときは手順2〜3を飛ばす）
2. 機能は「コンテンツを読み取る」「コンテンツを更新」だけON（挿入・コメント・ユーザー情報はOFF）
3. シークレット（`ntn_…`）をコピーしておく（Notionのページには貼らない）
4. Notion で **DB_ニュース** を開き、右上「•••」→「接続」→ 手順1のインテグレーションを追加
   - ME・データベースなどの親ページには接続しない

### 2. Cloudflare：Worker を作る

1. https://dash.cloudflare.com の「Workers & Pages」→「作成」→「Gitリポジトリをインポート」→ GitHub の `my-apps` を選ぶ
2. 設定
   - プロジェクト名：`news-reader`
   - ルートディレクトリ：`news-reader`
   - ビルドコマンド：空欄／デプロイコマンド：`npx wrangler deploy`
3. デプロイ後、Worker の「設定」→「変数とシークレット」で **シークレット**を2つ追加して再デプロイ
   - `NOTION_TOKEN`：手順1でコピーした `ntn_…`
   - `APP_KEY`：合言葉（16文字以上。パスワードマネージャーで作ると楽）
4. `https://news-reader.<あなたのサブドメイン>.workers.dev` が表示されたら完了

以後、このフォルダを GitHub で更新すると自動で再デプロイされる。

### 3. iPhone：ホーム画面に追加して、赤丸をオンにする

1. Safari で上のURLを開き、合言葉を入れる
2. 共有ボタン →「ホーム画面に追加」
3. ホーム画面のアイコンから開き、「アイコンに未読の数（赤丸）を出しますか？」の「オンにする」→ 通知を「許可」
   - iOS 16.4 以降。ホーム画面から開いたときだけ出せる（Safari のタブでは出せない）
   - 右上のメニュー →「通知を試す」で、すぐに数字と通知が来るか確かめられる

## よくあるエラー

| 表示 | 原因 |
| --- | --- |
| 合言葉が違います | APP_KEY と違う。右上のメニュー →「合言葉を消す」から入れ直す |
| インテグレーションが接続されていません | 手順1-4 の接続忘れ |
| Notion のトークンが正しくありません | NOTION_TOKEN の貼り間違い |
| Worker の設定が足りません | シークレット2つが未設定、または APP_KEY が16文字未満 |
| 本文を読み取れませんでした | サイトの作りが変わった（`src/extract.js` の `SITES` を直す）。一言要約と元の記事は見られる |
| 記事のサイトが表示を断りました | サイトが Cloudflare からの読み込みを断った。元の記事を開いて読む |
| アイコンに数字が出ない | ホーム画面から開いていない／通知を許可していない（設定アプリ → 通知 → 新聞） |
| 通知の保存先（KV）がありません | `wrangler.toml` の `[[kv_namespaces]]` が消えている |

## 開発

```sh
npm install
npm test               # Worker と本文抽出のテスト（Notion・新聞社・通知サーバーは偽物に差し替え）
npx wrangler dev       # ローカルで起動（.dev.vars に NOTION_TOKEN と APP_KEY を書く）
```

- `src/worker.js`：Notion API の中継・本文の読み込み・朝の通知（API バージョン 2025-09-03、データソース指定）
- `src/extract.js`：記事ページから本文の段落を抜き出す（サイトごとの決まりは `SITES`）
- `src/push.js`：Web Push（VAPID の鍵づくり・宛先の保存・中身の無い通知の送信）
- `public/`：画面（HTML/CSS/JS、サービスワーカー、アイコン）
- `scripts/make-icons.py`：アイコン画像の生成
