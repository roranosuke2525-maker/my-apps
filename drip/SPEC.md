# ドリップ（仕様書）

旧「コーヒー抽出PWA（Drip Note／Pour）」の作り直し。豆・レシピ・1杯ごとの記録を Notion に置き、
スマホのホーム画面から「豆を選ぶ → 気分を選ぶ → タイマーで淹れる → 味を付ける」までを1本の流れにする。

- 形：API版（Cloudflare Worker＋Notion API）。合言葉で開く。ホーム画面に追加できる（PWA）
- 置き場：`my-apps/drip/`（作りは `trip-shiori` に合わせる：`src/worker.js`・`public/`・`test/`）
- Notion の DB は 2026/11/16 に組み替え済み（下の「データ」）

## 目的

1. 豆の登録を楽にする：袋をカメラに映して「読む」を押すだけ。**写真は撮らない・保存しない**
2. レシピを Notion で持ち、そのままタイマーになる
3. 気分と前回の味から、挽き目・湯温・配分の調整を出す
4. 1杯ごとに Notion の抽出ログへ残し、豆の残量を減らす

## 画面

| 画面 | 中身 |
| --- | --- |
| ☕ 淹れる（最初の画面） | ① 今日の豆（在庫が「飲み中」「未開封」の豆。飲み頃の表示つき）② 気分（すっきり／甘め／しっかり／華やか／ほっと・なしも可）③ レシピ（⭐いつもの が先頭。その豆で前回使ったレシピに「前回」）→ **調整案** を出す → 「この数字で淹れる」 |
| ⏱ タイマー | レシピの「注ぎ方」を1手ずつ大きく表示（いま注ぐ量・合計g・次まで何秒）。手順の切り替わりで短く振動・音。蒸らし・落ち切りは押して記録 |
| 👅 味 | 酸味・甘さ・苦味・濃さ・後味を `弱い／ちょうど／強い` の3択で押す（初期値はちょうど）、総合★、フレーバー、一言メモ。「残す」で抽出ログへ |
| 🫘 豆 | 豆の一覧（飲み中・未開封・飲み切り）。右上の 📷 で読み取り。行を押すと編集（在庫・焙煎日・開封日・残量など） |
| 📖 レシピ | 一覧と編集。「この版を元に直す」で派生レシピを作る（元のレシピ を自動でつなぐ） |
| 📝 ログ | 最近の記録。豆ごと・レシピごとに絞る |

## 豆の読み取り（写真を撮らない）

1. 📷 を押すとカメラの映像を画面に流す（`getUserMedia`、背面カメラ）。シャッターは無い
2. 「読む」を押した瞬間の1コマだけを、メモリの中で縮小（長辺1024px・JPEG）して `/api/scan` へ送る。端末にもNotionにも画像は残さない
3. Worker が Claude API で袋の文字を読み、項目に分けて返す：ロースター・名前・生産国・地域・農園・品種・精製・焙煎度・焙煎日・内容量g・価格・フレーバー（DBの選択肢に寄せる）・読み取りキー（袋の特徴的な文字列）
4. Worker は読み取りキーと名前で DB_Beans を探し、近いものを候補で返す
   - 当たり → 「この豆ですか？」→ 開封・残量の更新だけ
   - 無し → 埋まった項目を見せて、直してから「登録」。ロースターは DB_Shop の名前で合わせる（無ければ新しく作るか選ぶ）
5. バーコードが写っていれば Claude が番号も読むので、読み取りキーに足す（iPhone の Safari には端末内のバーコード読み取り機能が無いため、別の部品は入れない）

- モデル：`claude-sonnet-5-5`（画像の文字読み。1回数円の見込み）。応答は JSON の形を決めて受け取る
- 送るのは「読む」を押した1コマだけ。連続では送らない

## 調整案のきまり（アプリの中で計算・Claude は使わない）

元の数字＝そのレシピの数字。同じ豆×同じレシピの前回のログがあれば、その実際の数字。

**前回の味から**（強い／弱い だけ見る）

| 前回 | 次の調整 |
| --- | --- |
| 酸味 強い | 挽き目 1クリック細かく・湯温 +2℃ |
| 酸味 弱い（平たい） | 湯温 +1℃ |
| 苦味 強い | 挽き目 1クリック粗く・湯温 −2℃ |
| 濃さ 強い | 湯 +10g（比率を薄く） |
| 濃さ 弱い | 豆 +0.5g か 挽き目 1クリック細かく |
| 甘さ 弱い | 4:6系は 1投目を −10g・2投目を +10g、それ以外は 挽き目 1クリック細かく |
| 後味 強い（渋い・えぐい） | 挽き目 1クリック粗く・かき混ぜを控える |

**気分から**

| 気分 | 調整 |
| --- | --- |
| すっきり | 比率 1:16.5 へ・挽き目 1クリック粗く |
| 甘め | 4:6系は 1投目を減らし2投目を増やす・湯温 −1℃ |
| しっかり | 比率 1:15 へ・挽き目 1クリック細かく |
| 華やか | 湯温 +2℃（浅煎りのとき） |
| ほっと | 湯温 −3℃・比率 1:15.5 へ |

- 1回で動かすのは 挽き目 ±2クリック・湯温 ±3℃・豆 ±1g まで。湯温は 80〜97℃ に収める
- 注ぎ方の各投の量は、湯gの変化に合わせて同じ割合で伸び縮みさせる
- 出した案は理由つきで1行ずつ見せる（例：「前回 酸味が強い → 1クリック細かく」）。手で直せる
- 淹れた数字と調整の理由を、ログの「次の調整」に残す

## データ（Notion）

| --- | --- | --- |
| DB_Beans（豆） | `collection://25c62844-acbe-80c4-9230-000b4ed3899b` | 名前・ロースター（→DB_Shop）・生産国・地域・農園・品種・精製・標高・焙煎度・焙煎日・開封日・内容量g・残量g・価格・フレーバー・商品URL・読み取りキー・評価・在庫（未開封／飲み中／飲み切り）・説明メモ・飲み頃（式・読むだけ） |
| DB_Brew Methods（レシピ） | `collection://25c62844-acbe-8002-9cb0-000b18e69fd9` | レシピ名・考案者・ドリッパー・豆g・湯g・比率（式）・湯温・挽き目・注ぎ方・向く焙煎度・いつもの・元のレシピ／派生レシピ・出典URL・メモ |
| DB_Coffee Brewing Log（抽出ログ） | `collection://21162844-acbe-801d-9540-000bac4ca660` | 場所（タイトル：Home／Office）・日付・豆・レシピ・グラインダー・ドリッパー・豆g・湯g・湯温・挽き目（選択：10〜30）・蒸らし・落ち切り・気分・酸味・甘さ・苦味・濃さ・後味・総合・フレーバー・次の調整・メモ |
| DB_Shop | `collection://33062844-acbe-81c5-85d5-000b725a6493` | 名前（ロースターの照合） |
| DB_Grinder | `collection://25c62844-acbe-8094-abdf-000b0a334597` | 名前（TIMEMORE NANO3・C2 MAX） |

- 注ぎ方の書き方：`0:00 60 / 0:45 120 / 1:30 180 / 3:30 外す`（時刻と、その時点までの**合計g**。数字の無い手順は文字だけ表示）
- 挽き目はログでは選択（文字）、レシピでは数字。アプリが変換する
- 淹れ終わり：ログを1件作る → 豆の残量g から豆gを引く（0以下なら在庫を「飲み切り」にするか聞く）→ 未開封なら「飲み中」にして開封日を今日に
- 場所は前回の値を引き継ぐ（Home／Office の切り替え）

## API（Worker）

| 道 | 中身 |
| --- | --- |
| `GET /api/data` | 豆（飲み切り以外）・レシピ・最近のログ60件・Shop・Grinder をまとめて返す |
| `POST /api/scan` | 画像（JPEG）→ Claude で読む → 項目＋DB_Beans の候補 |
| `POST /api/beans` ・ `PATCH /api/beans/:id` | 豆の登録・更新 |
| `POST /api/recipes` ・ `PATCH /api/recipes/:id` | レシピの登録・更新（派生は元のレシピをつなぐ） |
| `POST /api/logs` | ログを1件作り、豆の残量・在庫・開封日を直す |

- すべて `X-App-Key`（合言葉）が合わないと 401
- 圏外で押した「残す」は端末に残し、電波が戻ったら送る（旅のしおりと同じ）

## 秘密の値（wrangler secret put）

- `NOTION_TOKEN`：Notion 内部インテグレーション（コーヒーの5つのDBに接続しておく）
- `ANTHROPIC_API_KEY`：袋の読み取り用
- `APP_KEY`：合言葉（16文字以上）

## やらないこと

- 画像の保存・送りっぱなしの連続読み取り
- 豆購入検討（KISSA向け）・DB_Knowledge of Coffee には触らない
- 調整案に Claude を使うこと（きまりで足りなければ後で考える）

## 完成の目安

- 袋を映して「読む」→ 新しい豆が DB_Beans に入る（画像はどこにも残っていない）
- いつものレシピ × 気分「甘め」で調整案が出て、タイマーで淹れ、味を付けて残すと、抽出ログに1件・豆の残量が減る
- 次に同じ豆を選ぶと、前回の味から調整案が変わる
